## Recovered project decisions

### Single repository authority

Decision: `TAIJIFU-SITE` is now the official and only TAIJIFU repository. Everything recoverable from previous TAIJIFU repositories/projects is to converge here.

### Canon and public product

The repository currently materializes `TAIJIFU-CANON-1.0` and the structural counts 4 Bases / 10 Faixas / 32 Caminhos / 128 Núcleos.

The public product is expected to render Canon rather than maintain a competing curriculum.

### Identity v2.2 baseline

Recovered repository rules include:

- editorial martial composition rather than generic builder-card layout;
- original TAIJIFU emblem and movement gestures;
- asymmetric Base composition;
- Canon chapters;
- visual belt path;
- TAI = red;
- JI = blue;
- FU = yellow/gold;
- Integration/Survival = green;
- no gradient, neon, glow, haze, glassmorphism or faux material texture;
- mobile gutters >= 24px.

### Interactive web direction

The project has been moving toward a navigable Web v1 combining semantic/document navigation with an interactive Three.js projection. The renderer is a projection: graph layout choices do not become Canon by implementation alone.

### References gap

The `/referencias/` route has been retained while its official body remains unresolved in the currently recovered material. The project explicitly chose not to invent this body.

### CI classification

Recent GitHub Actions runs have failed before any workflow step executed. Ecosystem governance reviewed during this project classifies this type of state as pre-step infrastructure non-execution rather than evidence of a code-test failure. Repository-local CI policy should make this distinction explicit.

## Masters legacy

TAIJIFU Masters material is retained as project legacy and product/game archaeology. It must not silently redefine the martial Canon.

Recovered themes include:

- candidate → review → import → in-engine bench asset pipeline;
- rejection of showcase boards as pack-ready runtime assets;
- modular `Character Base Rig` / `Base Fighter` concept;
- separation between visual loadout and combat loadout;
- standardized visual slots/pivots/contracts;
- requirement that runtime assets be individually validated rather than approved from concept sheets.

These are valuable product/game-development sources. Their current status is `LEGACY` or `EXPERIMENTAL` until explicitly promoted in this repository.
